Remise à niveau d'un framework Java/Appium legacy

Reprise d'un framework de 4 ans en dette technique. Objectif : le rendre maintenable, performant et à l'état de l'art.

  • Modernisation complète du socle technique : Java 25, Appium Java-Client 10, Java Records, SLF4J/Logback — migrations enchaînées sans régression, refonte du système de logging pour un debugging précis par scénario de test
  • Refactoring en profondeur : suppression du code mort, nettoyage des dépendances — le framework pèse aujourd'hui la moitié de sa taille initiale
  • Stabilisation de l'exécution : FluentWait pattern, distribution automatique des tests sur un pool de devices BrowserStack diversifié (OS, modèles, tablettes, orientations portrait/paysage) — chaque scénario tourne sur un device différent
  • Exploitation avancée de BrowserStack : architecture du SDK en mode observability-only (le SDK instrumente les tests sans interférer avec la rotation custom des devices), activation de toutes les capabilities disponibles (network logs avec capture content, device logs, app profiling, video, geolocation, timezone), build naming dynamique intégrant plateforme/profil/tags Cucumber pour un suivi fin dans le dashboard — tirer le maximum de la plateforme au-delà de la simple exécution de tests
  • Système de cache BrowserStack : cache des apps (invalidation 24h, détection automatique DAILY/RELEASE) et cache des devices par plateforme — évite les appels API répétés et accélère l'initialisation des sessions

Création from scratch d'un framework TypeScript/WebDriverIO

Aucun framework TS n'existait chez Accor pour le mobile. Conception et développement intégral d'une solution industrielle multi-plateforme, multi-locale, orientée isolation complète des tests.

  • Architecture isolée par scénario : customisation de WebDriverIO pour reproduire le comportement TestNG — 1 scénario Gherkin = 1 session BrowserStack = 1 fresh install, via un système de split automatique des features et reload de session
  • Rotation atomique des devices : compteur partagé inter-workers avec lock fichier (proper-lockfile), garantissant un round-robin sans collision même à 10+ workers parallèles
  • Multi-locale natif : tags Cucumber (@locale, @language, @timezone) parsés automatiquement, chaque scénario s'exécute dans sa locale cible avec device, timezone et langue dédiés
  • Page Object Model cross-platform : sélecteurs Android (UiSelector) et iOS (XCUITest) unifiés dans une même classe, abstraction complète de la plateforme pour les step definitions
  • Cache BrowserStack & exécution parallèle : cache apps dual-build (daily/release, invalidation 24h) et cache devices par plateforme, exécution pilotable entièrement par variables d'environnement
Stack : TypeScript · WebDriverIO 9 · Appium 3 · Cucumber · BrowserStack · Node.js
