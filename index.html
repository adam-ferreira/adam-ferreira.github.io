All in a test repo shared between mobile and web.

Building the automation alongside the app

When I joined, the app was still being built, and the gamification scope with it. The challenge: automate at the pace of releases without slowing the developers down.

  • Test IDs placed directly in the app code. On mobile, a locator that finds a screen by its text breaks at the first translation or the first design change. I was the first QA automation engineer on the app to add the semantics myself in the Flutter code, following rules written with the tech leads, instead of waiting for the developers. The same locators work on iOS and Android, and they survive screen redesigns.
  • Interactive animations, untestable until then. They are made by the motion design team in a dedicated tool, and the tests could not see anything inside them. I wrote a tool that injects the test IDs straight into the animation files, checked the result against the Flutter runtime, then produced a version the designer can open in their own software to understand the change and make it themselves.
  • Test data created through APIs, not by hand. Testing a betting mission takes real bets, placed and then settled. I create them through APIs before each scenario, the same way production campaigns do, on a dedicated test account. The test only goes through the UI for what it actually checks: it stays short, and it doesn't break because another test touched the same data.
  • A nightly run across five regulated markets. Each country has its own rules, content and accounts. The nightly runs on each of them; every morning I triage the failures into three buckets: product bug, broken environment, flaky test. Only the first become tickets.
  • Going down to the mobile engine when a test fails for no reason. A visible button the test couldn't tap, a tab bar that vanished from the iOS accessibility tree, the Android system navigation bar swallowing taps: each time I traced the cause to how iOS, Android or Flutter behaves, and fixed it in the framework instead of working around it in the tests.
  • A method shared with the squad. A test plan per feature, a release test suite, and shared Claude Code skills that generate page objects from Figma designs and Jira tickets.

02

QA Automation Architect — ACCOR (CAC 40)

Nov. 2024 - March 2026 (Freelance)

Accor tests its ALL mobile apps (loyalty, booking, stay) with a four-year-old automated test framework carrying technical debt. I joined to run and maintain tests, and became the framework's technical go-to person.

Bringing a legacy framework up to date, then going further

  • Modernizing the framework without stopping the tests. Back-to-back Java and Appium client migrations with no regression. Along the way I removed dead code and rewrote the logs so they read scenario by scenario. The framework lost half its weight.
  • A different device for each scenario. Bugs specific to one model, a tablet or a landscape screen don't show up when every test runs on the same phone. I had each scenario dispatched to a different device on the BrowserStack device farm: failures became reproducible, and with app and device caching, sessions start faster.
  • A CI pipeline that finally tells you whether the release is good. Before, it ran the tests but stayed green no matter what, and it relied on a template shared with other projects that couldn't be adapted. I rewrote it for the team: it turns red as soon as the pass rate drops below a threshold, publishes the results to Jira and Xray, and alerts each team on Slack about its own failures.
  • Bringing within the tests' reach what used to escape them. Features behind a feature flag, store builds, TestFlight and Firebase distributions, and webviews behind the company WAF.
  • App bugs diagnosed for the developers. The iOS login made one run in five fail. I compared passing and failing sessions on the same build, isolated the cause, and worked on the fix together with the iOS tech lead. Same approach for expired sessions and missing consent screens.
  • A second framework, in TypeScript, built from scratch. There was no TypeScript framework for mobile at Accor. I built one, cross-platform and multi-locale, and documented how it compares with the Java stack.
