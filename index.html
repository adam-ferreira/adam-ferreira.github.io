QA Automation Engineer (Flutter mobile) — BETCLIC

March 2026 - Present (Freelance)

Betclic is rebuilding its iOS and Android app in Flutter. I automate the tests of the gamification features: missions and challenges, leaderboards, reward games, and boosts offered when placing a bet. The tests live in a repo shared between mobile and web.

Building the automation alongside the app

When I joined, the app and its gamification features were still being built. The tests had to keep up with each release without slowing the developers down.

  • Test IDs in the app code. On mobile, a locator based on the displayed text breaks with each translation or design change. I add the Flutter semantics to the app code myself, following rules agreed with the tech leads.
  • Test IDs in the animations. The interactive animations are made by the motion design team in a dedicated tool, and the tests could not reach their content. I wrote a tool that adds test IDs to the animation files, checked the result with the Flutter runtime, and produced a version the designer can open in their own tool to apply the change themselves.
  • Test data created through APIs. A betting mission needs bets that are placed and then settled. I create them through APIs before each scenario, on a dedicated test account. The UI is only used for what the test checks, so tests stay short and independent from each other.
  • A nightly run on five regulated markets. Each country has its own rules, content and accounts. Every morning I sort the failures into product bugs, environment issues and flaky tests. Only product bugs become tickets.
  • Failures investigated down to iOS, Android and Flutter. For example: a visible button the test could not tap, a tab bar missing from the iOS accessibility tree, the Android navigation bar intercepting taps. For each one, I found the cause in how the platform or Flutter behaves, and fixed it in the framework rather than working around it in the tests.
  • Shared tooling with the squad. A test plan per feature, a release test suite, and Claude Code skills that generate page objects from Figma designs and Jira tickets.

Accor tests its ALL mobile apps (loyalty, booking, stay) with an automated test framework started four years earlier, with technical debt. I joined to run and maintain the tests, and became the technical reference for the framework.

Modernizing an existing framework

  • Framework modernization. Java and Appium client upgrades, dead code removed, logs rewritten to read scenario by scenario. The framework is now half its previous size.
  • One device per scenario. Each scenario runs on a different device of the BrowserStack device farm, so bugs specific to a model, a tablet or an orientation show up and can be reproduced. Caching apps and devices shortened session start-up.
  • A rewritten CI pipeline. The previous pipeline stayed green whatever the results and depended on a template shared with other projects. The new one fails when the pass rate drops below a threshold, publishes the results to Jira and Xray, and notifies each team on Slack of its own failures.
  • Wider test coverage. Features behind a feature flag, store builds, TestFlight and Firebase distributions, and webviews behind the company WAF.
  • A second framework in TypeScript. Built from scratch, cross-platform and multi-locale, with a documented comparison against the Java stack.
